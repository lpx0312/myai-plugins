# ADR-0014 人读版附 L3 与超时统一

- 状态：已采纳（2026-10-24）
- 决策：用户（lipanx）
- 影响文件：`scripts/gluster-health.py`、`scripts/gluster-check.sh`、`scripts/heketi-check.sh`、
  `scripts/node-storage.sh`、`references/checks.md`（L1-07 人读版口径）、`tests/`

## 背景

三个独立问题：

1. 人读版 `gluster-health.py` 完全不做 L3：即使机器上有 kubeconfig，报告也永远打印
   "未做：Kubernetes 层"。HK-05/HK-06（容量对账、clusterid 一致性）只能靠 agent 手工拼。
2. 人读版把 heketi 用户写死 `admin`（契约脚本 `heketi-check.sh` 反而支持 `HK_USER`）。
3. 白名单承诺"轻命令 15s 超时"，但三个 shell 脚本的 `run()`（不带超时版）覆盖了
   `systemctl`/`gluster --version`/`df`/`lvs` 等轻命令；人读版在 py2 下
   `communicate(timeout=)` 分支被跳过，**完全无超时**，一条命令卡死整个巡检。

另有一处规范违背：checks.md L1-07 规定 heal 输出里砖非 Connected 只"关联 L1-05"、
不计入计数；人读版却把它记成独立 P0，虚增 P0 计数。

## 决策

1. **人读版附 L3**：新增 `--kubeconfig`（可选）。给出时本机执行 kubectl：
   current-context（只打印供核对，**绝不 use-context**）、`get sc/pvc/pv/events -o json`、
   按需 `get secret -o jsonpath={.type}`（K8S-02 两阶段）、有挂载类事件时才拉 `pods`。
   判定覆盖 K8S-01..06 与 HK-05/06（heketi 按需逐卷 `volume info` 取 Size）。
   L3 报告新增"五、Kubernetes"节；未给 kubeconfig 时保持原样并说明原因。
2. **`--heketi-user`**：默认 admin；用户名过 `^[A-Za-z0-9_.-]+$` 白名单后才进
   awk `-v` 与命令行（防注入）。
3. **超时统一**：shell 侧全部轻命令改 `run_to 15`（topology 60s、v info/status 60s、
   heal 120s 不变），删除无超时的 `run()`/`run_hk()`/`hk()` 死代码；
   py 侧新增 `_popen()`：py2/py3 同走 `threading.Timer` 兜底杀进程，超时 rc=124 落 SKIP。
4. **单一根因修正**：heal 砖非 Connected 在人读版改为 **INFO**（不计数），
   与 checks.md/ADR-0004 对齐；渲染支持 INFO 级。
5. **孤儿砖**：人读版每节点新增 `ls -d /var/lib/heketi/mounts/vg_*/brick_*/brick`
   清单，与 L1-04 期望清单求差集（ADR-0011 判据 C）：缺砖 P0（与 findmnt 已判 P0 的
   去重）、孤儿砖 P2；采集失败落 SKIP，无砖节点不产生噪音。
6. fixtures 同步扩容：`node.*.lsbricks.out`、`k8s.{ctx,sc,pvc,pv,events,secret,pods}.out`、
   `heketi-vinfo.out`；bad 组注入孤儿砖/扩容门开/容量虚标/挂载事件+Pod 未 Running。

## 后果

- 人读版与契约脚本的检查范围差距缩小到：runbook 场景与 `##STATE` 契约仍只属于后者；
  两处维护的判据清单变长（新增 K8S/HK 判据），改判据时记得同步（tests/README §4）。
- py2 的超时不再依赖 `communicate(timeout=)`，Windows 控制台编码问题维持 `emit()` 方案。
- kubectl 仅在本机执行、`-o` 形态遵守 ADR-0003（json / jsonpath 仅 K8S-02）。
