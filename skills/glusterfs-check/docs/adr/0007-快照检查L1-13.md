# ADR-0007 快照检查（L1-13）

- 状态：已采纳（2026-10-21）
- 决策：用户（lipanx）
- 影响文件：`references/checks.md` L1-13、`references/thresholds.md` §2、`scripts/gluster-check.sh`

## 背景

`snapshotCount` 早在 L1-04 的关键字段里采集，但全技能没有任何判据用它——采了不用，等于漏掉一类风险：
快照会持续占用 thin pool 空间，并且**阻止卷删除/缩容**。heketi 管理的卷默认 `Snapshot: Disabled`，
所以 `snapshotCount > 0` 基本可以断定是人工用 gluster 命令建的。

## 决策

新增 **L1-13 快照数量**：

- `snapshotCount = 0` → PASS；
- `snapshotCount ≥ 1` → **P2**，证据写卷名 + 数量；
- 与容量风险叠加时（`data_percent ≥ 80%` / `df ≥ 80%`）按 L1-09/L1-10 **照常定级，不重复计**（单一根因原则）；
- 字段缺失（老版本 XML 无该节点）→ `SKIP(field-missing:snapshotCount)`，不默认成 0。

脚本在逐卷循环里输出 `##L1-13 vol=<v> snapshotCount=<n>`，与 L1-07 共用同一次 `gluster v info <vol> --xml`，
不额外增加调用。

## 后果

- `SKILL.md` §5 的 L1 范围从 09–12 扩到 09–13。
- 快照不能由巡检清理，只能人工确认留存理由后处理（本技能不给清理命令）。
