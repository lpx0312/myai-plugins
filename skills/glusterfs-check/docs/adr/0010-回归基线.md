# ADR-0010 回归基线（golden sample + 静态校验）

- 状态：已采纳（2026-10-21）
- 决策：用户（lipanx）
- 影响文件：`tests/`

## 背景

判据和阈值写得很细，但改脚本没有任何回归手段：脚本输出结构一变，`checks.md` 的判据就悄悄失效，
而且没人会发现。现场也没有"标准输出长什么样"的参照。

## 决策

建立 `tests/`，**不依赖任何主机**：

1. `tests/samples/*.golden`：每个脚本一份**结构样例**。id / IP / 时间一律用占位符
   （`vol_<id>`、`<vgid>`、`<ISO8601>`），只表达"块长什么样、状态行怎么写"，**不做逐字 diff**——
   真实环境每次 id 都变，逐字比对必然误报。
2. `tests/verify-scripts.sh`：静态校验，`bash tests/verify-scripts.sh` 一条命令跑完：
   `bash -n`、`set -u`、`LC_ALL=C`、无裸 `|| true`、无硬编码口令、无远端落盘命令、
   有 `_state` 与 `##END`、有 `CMD:` 行。
3. 新增检查项的清单写进 `tests/README.md`（判据 → 阈值 → 脚本 → 样例 → 静态校验 → 术语/ADR）。

## 后果

- 改脚本的最低门槛从"看起来能跑"变成"静态校验全绿"。
- 样例不是契约测试：它不验证真实集群输出，只验证结构没走样；真实回归仍需在集群上跑一次冒烟。
