# ADR-0012 人读版报告脚本

- 状态：已采纳（2026-10-21）
- 决策：用户（lipanx）
- 影响文件：`SKILL.md` §0/§1/§3/§4.0/§7、`references/commands.md` §1、`scripts/gluster-health.py`、
  `tests/test-report.py`、`tests/fixtures*/`

## 背景

2026-10-21 实际巡检时，用户把 `gluster-check.sh` 的输出贴回来说「根本看不懂」——
`##STATE` 契约加 XML 是给 agent/机器解析的，人读需要另一层。

于是加了一个 Python 的"人读版"：跑同一组只读命令，输出中文表（节点 → 卷 → 容量 → heketi → 结论）。
上线后立刻踩到两个**只在这种解析里才存在**的坑：

1. 42 上是 python 2.7，`str(数字)` 得到字节串，`unicodedata.east_asian_width()` 只吃 unicode，
   表格对齐时直接 `TypeError`。表头是 unicode 字面量所以没事，数据行第一格就炸。
2. 只有走 ssh 的 43/44 出现「砖挂载丢失」，来源显示 `Permanently`、类型 `added`——
   `ssh` 首次连接打的 `Warning: Permanently added ...` 被并进 stdout，按行序解析时把 findmnt 第 1 行顶掉。
   42 是本机执行所以无事，这个分布本身就是证据。

两条都不是集群问题，是"人读解析"引入的假阳性。

## 决策

1. **保留两套输出，互不替代**：`##STATE` 契约脚本（`gluster-check.sh` / `node-storage.sh` /
   `heketi-check.sh` / `k8s-check.sh`）仍是可审计的机器契约；`scripts/gluster-health.py` 只负责"给人看"。
   判定阈值同 `references/thresholds.md`，改阈值必须两边同步。
2. **解析按标记、不按行序**：远端逐砖输出前打 `##F <砖目录>`，解析端按目录名匹配。
   任何多余行（ssh 警告、motd、profile 的 echo）都污染不了判定。
3. **连接姿势补 `LogLevel=ERROR`**：从源头压掉 "Permanently added" 这类 stderr 噪声。
4. **采集失败不当 0**：`v status` 失败 → 在线列 `n/a` + `SKIP`；`heal` 失败 → `?` + `SKIP`。
   与 ADR-0002 同一条原则：`ERR`/`SKIP` 不得落成"正常"。
5. **python 2.7 与 3.x 双兼容**：所有进表格的文本先过 `_u()` 统一成 unicode；
   不用 `argparse`（py2 + `LANG=C` 下打印中文帮助会抛 `UnicodeEncodeError`）。
6. **它只跑白名单命令**（`references/commands.md`），不写远端文件、不触发 heal；`--verbose` 会打印
   本次执行的全部命令，供 §7 自检用。

## 后果

- 人读脚本的判定逻辑与阈值表是**两处维护**：改 `thresholds.md` 必须同时改脚本，否则两边结论会分叉。
  缓解手段是 `tests/fixtures*` 的端到端断言（正常态 P0×0、故障态 P0×5）。
- 需要目标机或跳板机有 python（CentOS 7 自带 2.7）。没有 python 的环境仍用 bash 契约脚本，功能不受影响。
- `tests/test-report.py` 把上面两个坑固化成断言：噪音行必须被忽略、按目录名匹配、
  缺数据必须 `SKIP`；改动解析逻辑时先跑它。
