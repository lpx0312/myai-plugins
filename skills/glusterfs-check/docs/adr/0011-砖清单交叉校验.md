# ADR-0011 砖清单交叉校验

- 状态：已采纳（2026-10-21）
- 决策：用户（lipanx）
- 影响文件：`references/checks.md` L1-11 判据 C、`scripts/node-storage.sh`

## 背景

`node-storage.sh` 是**单机自证**：它枚举 `/var/lib/heketi/mounts/vg_*/brick_*/brick`，
本机没有砖就打印 `##NO_BRICK_DIRS` 直接结束。问题是"该有砖却没砖"和"本机本来就没有砖"
输出完全一样——挂了、目录被删了、机器换了，看起来都像"干净"。

## 决策

**期望清单来自集群，现状来自主机，两者求差集**：

1. `node-storage.sh` 增 `##BRICKLIST` 块，显式列出本机砖目录（不再靠 L1-11 的逐条输出反推）。
2. `checks.md` L1-11 增**判据 C**：
   - 期望清单（L1-04 的 brick 路径）有、本机没有 → **P0**（等同该砖不可用）；
   - 本机有、期望清单没有 → **P2**（孤儿砖，heketi 无记录但仍占池空间）。
3. 单机脚本不自行下结论，只提供证据；差集判定在报告侧完成（脚本看不到集群视图）。

## 后果

- 报告里 L1-11 的判定必须同时引用 L1-04 与 `##BRICKLIST`，不能只看 `findmnt`。
- 只授权了单台主机时，判据 C 标 `SKIP(host-not-authorized)`——没有清单就谈不上差集。
