# ADR-0005 版本不在支持矩阵仍执行

- 状态：已采纳（2026-10-21）
- 决策：用户（lipanx）
- 影响文件：`SKILL.md` §1、`references/checks.md` L1-02

## 背景

原文：版本偏离基线（glusterfs 8.5 / heketi 9.0 或 10.4）时"相关检查项标 `SKIP(unsupported)`"。
但绝大多数检查项（`gluster v info/status`、`heal info summary --xml`、`df`、`lvs`、`heketi topology info`）
的命令与字段在 gluster 9/10/11、heketi 9/10 上基本一致。一刀切 SKIP 等于技能在这些版本上直接失效，
而现实中巡检需求恰恰最多出现在"版本不太旧也不太新"的环境。

## 决策

版本偏离基线时**不再整体 SKIP**，改为：

1. 照常执行全部检查；
2. 报告头部固定声明「版本不在支持矩阵（基线 glusterfs 8.5 / heketi 9.x|10.4），结论仅供参考」；
3. 只有当**命令不存在**、或**关键字段缺失导致判据无法成立**时，才对**该单项**标
   `SKIP(unsupported: <缺什么>)`。

## 后果

- 判据实现必须"字段缺失 → 不下结论"，不能把缺失字段当默认值（例如 `replicaCount` 缺失不能默认 1 判成无冗余）。
- 需要在报告里保留版本行（`gluster --version`、`heketi-cli --version`）作为可追溯依据。
