# ADR-0002 脚本输出契约（三态）

- 状态：已采纳（2026-10-21）
- 决策：用户（lipanx）
- 影响文件：`scripts/*.sh`、`SKILL.md` §7、`references/checks.md` 约定段

## 背景

改造前四个脚本统一用 `cmd 2>&1 || true` 吞掉一切错误。后果是：

- 命令失败、无权限、超时，输出都是"空"；
- 报告层只有 PASS / P0 / P1 / P2 / SKIP 五种判定，空输出极易被写成 PASS；
- `timeout 120` 到期后同样静默，分不清"0 条待愈合"和"根本没查成"。

另外 `lvs` 的小数点受 locale 影响（可能输出 `0,28`），阈值比较会失效。

## 决策

每个检查段固定三行结构：

```
##<ID> CMD: <实际执行的命令，凭据脱敏>
<命令原始输出>
##STATE <ID> OK | ERR rc=N | SKIP <reason>
```

配套规则：

1. **禁止裸 `|| true`**。`ERR` 与 `SKIP` 是唯一合法的失败表达。
2. `timeout` 退出码 124 一律映射为 `SKIP timeout=<n>s`，不得当成空结果。
3. 所有脚本 `export LC_ALL=C LANG=C`。
4. heketi 凭据：就地读 `/etc/heketi/heketi.json`，不硬编码、不从命令行传；打印命令时 secret 显示为 `***`。
5. heal 检查只对有副本的卷执行；Distribute-only 卷输出 `SKIP distribute-only`（与 `checks.md` 前置约定一致）。

## 后果

- 报告层（`SKILL.md` §7）必须把 `ERR` / `SKIP` 落成 `SKIP(命令失败|超时|原因)`，**不得判 PASS**。
- 新增检查项时，脚本与判据必须同时更新，否则自检会暴露"有检查无输出"。
- 输出体积变大（每个命令多一行 `CMD`），换来的是可审计：报告里的"本次执行的命令"可直接来自脚本。
