# ADR-0008 巡检预算与卷数上限

- 状态：已采纳（2026-10-21）
- 决策：用户（lipanx）
- 影响文件：`SKILL.md` §0、`references/checks.md` 约定、`scripts/gluster-check.sh`

## 背景

技能写"整体巡检总预算 10 分钟"，同时允许 `heal info` 每卷 120s。两者在卷多时直接冲突：
50 个卷 = 100 分钟，预算是它的 10 倍。原文档没有降级策略，实际执行只能靠 agent 自己临时决定——
这是最坏的一种"没有规则"。

## 决策

1. 总预算 10 分钟不变。
2. `heal info` 每卷 120s 超时不变（超时 → `SKIP(timeout=120s)`）。
3. **卷数上限**：`HEAL_MAX_VOLUMES`（默认 20）。超过上限的卷，其 heal 检查标 `SKIP(budget:volumes>20)`，
   并在报告里**列出这些卷名**，提示可单独发起聚焦巡检。
4. **重点卷优先**：需要突破上限时，用 `HEAL_VOLS="vol_a vol_b"` 指定要查的卷
   （判定口径上优先选：有快照的、`distCount>1` 的、有非 Connected 砖的、对应 PVC 出过 `FailedMount` 的）。
5. 其余检查项（peer、卷信息、df、lvs、heketi 拓扑）不受该上限影响——它们与卷数无强线性关系。

## 后果

- 报告必须能区分"查了且是 0"与"没查"，靠 `SKIP(budget:...)` 表达。
- 上限可被环境变量覆盖，但报告头部必须写明本次用的值。
