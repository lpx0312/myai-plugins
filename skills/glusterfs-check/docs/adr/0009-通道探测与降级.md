# ADR-0009 通道探测与降级

- 状态：已采纳（2026-10-21）
- 决策：用户（lipanx）
- 影响文件：`SKILL.md` §0

## 背景

原文写"连接优先用环境里可用的 ssh MCP；没有 MCP 时才用本机 `ssh`"。
但"配置了 MCP"和"MCP 工具真的可用"是两件事：本机就存在 `SSH_MCP_CONFIG` 指向配置文件、
而会话里根本拿不到 ssh MCP 工具的情况。没有降级规则时，agent 会在两种坏结果之间摇摆：
要么误判"没有 MCP"直接换通道却不在报告里说明，要么反复重试一个不存在的工具。

## 决策

1. **探测**：先看当前会话是否真的暴露了 ssh MCP 的"执行命令"能力（工具存在且可调用）。
2. **可用** → 走 MCP。
3. **不可用** → 回退本机 `ssh`，命令姿势与 `SKILL.md` §0 中的固定姿势完全一致
   （`BatchMode=yes`、`ConnectTimeout=8`、`StrictHostKeyChecking=no`、`UserKnownHostsFile=NUL`）。
4. 无论走哪条，**仅限用户点名的主机**；报告头部记 `channel=mcp` 或 `channel=local-ssh`。
5. 不因为通道问题放宽任何只读约束；降级只影响"怎么连"，不影响"能跑什么"。

## 后果

- 报告里能看出本次用什么通道，便于复核"为什么没走 MCP"。
- 换通道不需要用户再次授权——授权看的是目标和范围（ADR-0001），不是通道。
