# ADR-0004 heal 定级、去重与信息项

- 状态：已采纳（2026-10-21）
- 决策：用户（lipanx）
- 影响文件：`references/checks.md` L1-07 / HK-02、`references/thresholds.md` §1 §2 §4

## 背景

原文有三处互相打架或会放大噪音的地方：

1. `checks.md` L1-07：「`totalEntries > 0` 首见 P1；复查后仍 >0 或 ≥100 → P0」——`≥100` 是"首见即 P0"
   还是"复查仍 ≥100 才 P0"，两种读法都成立。
2. `thresholds.md` §4：「复查归零 → 保持 P1」。已经愈合了还永久挂一条 P1。
3. 同一根因双计：brick 离线时 L1-05 记 P0，L1-07 又因 `status != Connected` 记 P1，报告头部计数虚高。
4. `HK-02`：设备 online 但无砖、Used=0 判 P2"疑似未纳管"——空盘是正常状态（新加盘/待分配）。

## 决策

**heal 定级**

| 条件 | 判定 |
|---|---|
| 首见 `totalEntries ≥ 100` | **P0**（无需复查：百条积压已非瞬时抖动） |
| 首见 `0 < totalEntries < 100` | **P1**，标注"待复查" |
| 复查（≥10 分钟后）仍 > 0 | 升 **P0** |
| 复查归零 | **关闭**，降为 INFO（记录"曾瞬时非 0"），不再计 P1 |
| `splitBrain > 0` | **P0** |

**去重**：L1-07 遇 `brick.status != Connected` 时，只写"关联 L1-05"，**不单独计入 P1 计数**。

**信息项**：新增 `INFO` 判定，用于"事实为真但无需处置"的情况，不计入 P0/P1/P2 计数：

- `HK-02` 空设备（online、无砖、Used=0）→ `INFO 空盘待分配`；
- heal 复查归零 → `INFO 曾瞬时非 0`。

## 后果

- 报告判定列允许值扩为：`PASS` / `P0` / `P1` / `P2` / `INFO` / `SKIP(原因)`。
- 头部结论行增加 `INFO × n`。
- 计数口径唯一：一个根因只记一次，最严重的那级。
