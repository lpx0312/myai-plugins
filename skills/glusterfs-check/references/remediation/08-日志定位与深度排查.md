# 08 · 日志定位与深度排查

> **本文档仅供人工执行。本技能只做定向只读检查，不做日志级别调整、不做 heal 触发。**
> 风险等级：**低**（只读）/ **中**（临时调日志级别）；是否需要停机：不需要。

## 日志在哪

| 组件 | 路径 | 用途 |
|---|---|---|
| glusterd | `/var/log/glusterfs/glusterd.log` | 集群成员、卷操作、brick 启动失败 |
| brick | `/var/log/glusterfs/bricks/<brick名>.log` | 单块砖的读写错误、盘满、元数据问题 |
| self-heal 守护 | `/var/log/glusterfs/glustershd.log` | heal 失败、split-brain、锁冲突 |
| 客户端挂载 | `/var/log/glusterfs/<mount点>.log` | 客户端侧 `Transport endpoint is not connected` 等 |
| heketi | `/var/log/heketi/heketi.log` 或 `journalctl -u heketi` | 建卷/删卷/扩容失败、DB 锁 |
| k8s 侧 | `kubectl get events`、`kubectl logs` | 挂载失败、权限拒绝 |

## 常规查看姿势（只读）

```bash
# glusterd：近 2 小时错误
journalctl -u glusterd --since "-2h" --no-pager | grep -iE 'error|failed' | tail -50

# brick：近 200 行
tail -200 /var/log/glusterfs/bricks/<brick名>.log

# 自愈守护
tail -200 /var/log/glusterfs/glustershd.log | grep -iE 'error|split|fail'

# heketi
journalctl -u heketi --since "-2h" --no-pager | tail -100
```

## 常见错误 → 含义 → 方向

| 日志关键字 | 含义 | 处理方向 |
|---|---|---|
| `no space left on device` | brick 所在盘/inode 满 | `05` 扩容 / 清理业务数据（人工确认后） |
| `Transport endpoint is not connected` | 写入中途失败或客户端连接断开 | 查 brick 是否在线（`03`）、盘是否满 |
| `brick ... is not a part of the volume` | `trusted.glusterfs.volume-id` 丢失（常因 `mkfs`） | **不要**盲目重建；按"元数据恢复"流程取值补回 |
| `Failed to find parent dir .../.glusterfs` | brick 根缺 `.glusterfs`（index xlator 起不来） | 建目录后拉起（人工，注意权限） |
| `Brick is offline` | brick 进程不在或挂载丢 | `03` |
| `split-brain` | 副本内容冲突，需人工裁决 | 见下节，**禁止**直接 `heal full` |
| `lock ... failed` / `EIO` | 客户端 IO 错误、锁冲突 | 查网络/后端盘；结合 brick 日志 |
| heketi `database is locked` | heketi DB 并发/异常 | 重启 heketi 需人工；先备份 DB |

## split-brain 处理（高危，必须人工决策）

巡检只能告诉你"有几条 split-brain"，不能替你选哪份数据是对的。

```bash
# 确认范围（只读）
gluster v heal <vol> info summary --xml
gluster v heal <vol> info split-brain      # 会列出冲突文件，大卷慎用
```

处理原则：

1. **先确认业务能否停机**。split-brain 处理期间该文件不可用。
2. 选定"权威副本"（最新、最完整的那份），依据是业务方确认，而不是文件时间戳猜。
3. 常见手段：把非权威副本上的冲突文件移走（在 brick 侧，人工），再让 heal 补回。
4. **不要**直接 `gluster v heal <vol> full`——可能把错误副本覆盖到正确副本上。

> 这一节的所有动作都是写操作，本技能不会执行，也不提供可直接粘贴的自动化脚本。

## 收集报障材料（人工执行）

```bash
mkdir -p /tmp/gls-diag-$(date +%Y%m%d)
gluster v list                     > /tmp/gls-diag-*/vol-list
gluster v status --xml             > /tmp/gls-diag-*/status.xml
gluster peer status                > /tmp/gls-diag-*/peer
gluster v info --xml               > /tmp/gls-diag-*/info.xml
df -h /var/lib/heketi/mounts       > /tmp/gls-diag-*/df
lvs                                > /tmp/gls-diag-*/lvs
```

采集时注意：**不要把 `/etc/heketi/heketi.json`（含明文口令）和 secret 内容打包外发**。

## 临时调日志级别（只在窗口内，事后必须还原）

```bash
# 调高
gluster v set <vol> diagnostics.brick-log-level DEBUG

# 复现/观察后立刻还原
gluster v set <vol> diagnostics.brick-log-level INFO
```

风险：DEBUG 会快速写满日志分区，进而把 brick 盘写满。**默认不要做**；确需时限定时间并盯 `df`。

## 明确禁止

- 长期开 DEBUG。
- 用 `heal full` 当"万金油"。
- 删 `.glusterfs`、`rm -rf` brick 目录"重置"。
- 把客户端挂载点 `umount` 当成排查手段（会中断业务）。
