# 07 · StorageClass 基线修正

> **本文档仅供人工执行。本技能不修改任何 k8s 资源。**
> 风险等级：**中**（影响新建 PVC）；是否需要停机：不需要；是否可回滚：可（有备份），删除 SC 期间无法新建 PVC。

## 适用

巡检命中 K8S-01：

- `allowVolumeExpansion: true` → 存在被 `kubectl edit pvc` 扩成高风险盘的风险
- 缺 `user.heketi.arbiter true` / `user.heketi.average-file-size 1` → 仲裁节点容量与数据节点不匹配（见 `06`）
- `clusterid` / `resturl` 为空或与 heketi 实际不一致（HK-06）

## 基线参数

```yaml
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: <sc-name>
parameters:
  clusterid: <heketi cluster id>
  restauthenabled: "true"
  resturl: http://<heketi-host>:8080
  restuser: admin
  secretName: glusterfs-admin-secret
  secretNamespace: kube-system
  volumeoptions: user.heketi.arbiter true,user.heketi.average-file-size 1
provisioner: kubernetes.io/glusterfs
reclaimPolicy: Delete
volumeBindingMode: Immediate
allowVolumeExpansion: false     # 关键：必须 false
```

## 步骤（SC 的参数基本不可原地改，需重建）

```bash
# 1) 备份（必须）
kubectl get sc <sc-name> -o yaml > sc-backup-$(date +%Y%m%d).yaml
cp sc-backup-*.yaml sc-new.yaml

# 2) 改 sc-new.yaml：allowVolumeExpansion: false；补 volumeoptions；核对 clusterid/resturl
vi sc-new.yaml

# 3) 删除旧 SC（不影响已 Bound 的 PVC；期间无法新建 PVC）
kubectl delete sc <sc-name>

# 4) 重建
kubectl apply -f sc-new.yaml

# 5) 校验
kubectl get sc <sc-name> -o yaml
```

> 删除 SC 期间**存量 PVC 正常工作**，只是建不出新的。请在业务低峰做，并在变更单里写明这个窗口。

## 关键点

- **只影响新建**：已经存在的卷/PVC 不会因为改 SC 而改变（arbiter 参数、扩容门都是如此）。
- **不要改 `resturl` / `clusterid` 去"修"别的问题**：这两个值错了会让新 PVC 建到别的集群或直接失败。改动前先 `heketi-cli cluster list` 核对。
- 若 SC 名字被业务大量引用（`storageClassName` 字段），重建时必须用**同名**，否则新 PVC 找不到 SC。

## 校验

```bash
# 参数核对
kubectl get sc <sc-name> -o jsonpath='{.allowVolumeExpansion}{"\n"}{.parameters.volumeoptions}{"\n"}'

# 人工建一个测试 PVC 验证（验证完立刻删除）
kubectl apply -f - <<'EOF'
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: sc-selftest
  namespace: default
spec:
  accessModes: [ReadWriteOnce]
  resources:
    requests:
      storage: 1Gi
  storageClassName: <sc-name>
EOF

kubectl get pvc sc-selftest -w        # 期望 Bound
kubectl delete pvc sc-selftest
```

## 明确禁止

- 改 SC 的 `reclaimPolicy`（会改变删除 PVC 时的后端行为）。
- 在未备份的情况下删除 SC。
- 用 `kubectl patch` 试图改 SC 的 `parameters`（多数字段不可变，会报错或行为不确定）。
- 把"关闭扩容门"理解成"已有高风险盘被修复"——它只防止新增。
