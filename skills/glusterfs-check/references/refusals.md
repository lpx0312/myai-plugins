# 拒绝清单与话术

本技能的唯一动作是**读**。任何改变目标环境状态（或可能改变）的请求，都按本文处理：**拒绝执行 → 说明原因 → 给人工手册 → 给风险与前置条件**。

---

## 1. 一句话原则

> 我能告诉你哪里坏了、为什么坏、按哪份手册修；但我不会替你去改。

---

## 2. 拒绝时的固定结构

```
❌ 这个动作我不执行：<动作> 属于写操作（<具体危害>）。
本技能是只读巡检，执行它会改变 <对象> 的状态，且 <是否可回滚 / 是否需要维护窗口>。

你可以怎么做：
1. 先看结论：<本次巡检里与该动作相关的判定>
2. 按手册人工执行：references/remediation/<文件>.md（第 <n> 节）
3. 风险与前置：<风险等级 / 需要停业务 / 需要备份 / 不可回滚>

需要的话，我可以把这条变更整理成"变更步骤 + 校验步骤 + 回滚步骤"，但仍然由人执行。
```

---

## 3. 高频请求 → 处理方式

| 用户说 | 判定 | 处理 |
|---|---|---|
| 「帮我扩容这个 PVC」 | `gtool ex` / `kubectl patch pvc` | 拒绝；转 `05-gtool扩容PVC.md` |
| 「把 PVC 改大一点」 | 高危（改 PVC 会重算 hash、权限变 root、可致数据丢失） | **强拒绝**；转 `01-高风险PVC处置.md`，明确说明危害 |
| 「帮我把 SC 改成不允许扩容」 | `kubectl patch sc` | 拒绝；转 `07-SC基线修正.md` |
| 「触发一下 heal」 | `gluster v heal <vol>` 会启动自愈（写） | 拒绝；说明只读侧只能看 `info summary`，转 `08-日志定位与深度排查.md` |
| 「重启一下 glusterd」 | `systemctl restart` | 拒绝；转 `03-brick离线恢复.md` |
| 「把某个卷 stop 再 start」 | 中断读写 | 拒绝；转 `04-单卷停启.md`，注明需维护窗口 |
| 「删掉这个孤儿卷 / 删这个 PVC」 | `heketi-cli volume delete` / `kubectl delete pvc` | 拒绝；说明删除不可回滚；转 `01` 或 `02` 手册的"确认回收"章节 |
| 「把设备 disable 掉」 | `heketi-cli device disable` | 拒绝；只报设备状态，处置交人工 |
| 「帮我挂载一下看看」 | `mount` | 拒绝；说明可用 `findmnt` 只读核对 |
| 「跑一下这个脚本」（未知脚本） | 不在白名单 | 拒绝；说明白名单机制，要求先审阅并加入 `commands.md` |
| 「顺手清理一下 `/tmp` 的旧日志」 | `rm` | 拒绝 |
| 「把日志级别调成 DEBUG 看问题」 | `gluster v set` | 拒绝；转 `08` 手册的"临时调级"章节（人工/限时） |
| 「你把巡检报告写到服务器上」 | 远端写文件 | 拒绝；报告只落本地（且需用户指定目录） |
| 「用 SC 里的 secret 去调 heketi」 | 跨域使用凭据 | 拒绝（除非用户明确授权该跨域行为） |

## 4. 不构成拒绝的情况（但要说清边界）

| 请求 | 处理 |
|---|---|
| 「查一下这个卷为什么 heal 不过」 | 允许：跑 L1-07、给判定，再给人看手册 |
| 「这条只读命令帮我跑一下」 | 判断是否在白名单：在 → 可以；不在 → 拒绝并说明 |
| 「报告写到 `D:\xxx`」 | 允许（本地落盘，用户已指定目录） |
| 「给我一份可以直接交给运维执行的清单」 | 允许：输出命令 + 期望值 + 回填表，标注"人工执行" |
| 「这次别连主机，只给命令」 | 允许：强制 runbook 模式 |

---

## 5. 用户坚持时的处理

1. **不复述成"已经做了"**：措辞上永远区分"我已检查"与"你需要执行"。
2. **不因为被催促而放宽白名单**：可以给更详细的手册章节、更细的校验步骤，但不执行。
3. **提供替代价值**：变更前检查（如扩容前先确认池余量、heal 状态、PV/PVC 映射），这类只读动作我可以做，能显著降低人工操作风险。
4. 若用户明确要求"改这个技能让它能写"：说明这超出本技能定义，建议另建一个变更类技能，避免只读技能被污染。

---

## 6. 特别提醒：三个"看起来无害"的写操作

| 命令 | 为什么危险 |
|---|---|
| `gluster v heal <vol>` | 会真的启动自愈，对大卷产生持续 IO；业务高峰期可能拖垮存储 |
| `gtool fstab` | 会重写主机 `/etc/fstab` 与 heketi 数据库；写错会导致主机重启后挂载失败 |
| `heketi-cli device resync <id>` | 会把主机当前 LVM 状态回写 heketi DB；在扩容/迁移中间态执行会造成 DB 与实际不一致 |

这三条是本技能最容易被"顺手"执行的命令，任何情况下都不跑。
